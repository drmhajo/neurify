# التحقق من Android بعد نقل API إلى Supabase

## ما الذي تغيّر

أصبح تسجيل الحسابات والموافقة عليها وتسجيل الدخول المركزي يستخدم وظيفة Supabase الثابتة عبر HTTPS:

`https://zyszoiezbbrunkgscwth.supabase.co/functions/v1/central-registration`

ولا تعتمد هذه العمليات على رابط المعاينة المؤقت أو على خادم التطوير. يُضمّن التطبيق الرابط والمفتاح العام فقط؛ أما مفتاح الخدمة ورمز التفويض فيبقيان داخل بيئة Supabase ولا يضافان إلى الحزمة.

| العملية | المسار الحالي | الحماية |
| --- | --- | --- |
| طلب حساب جديد | وظيفة Supabase عبر HTTPS | كلمة المرور مشتقة بـ PBKDF2 ولا تخزن كنص صريح |
| مراجعة الطلبات | وظيفة Supabase عبر HTTPS | رمز الموافقة المركزي مطلوب ولا يحفظ في التطبيق |
| تسجيل الدخول | وظيفة Supabase عبر HTTPS | لا يسمح بالدخول إلا بعد الاعتماد |
| تسجيل جهاز Push | وظيفة Supabase عبر HTTPS | حساب معتمد وإثبات قصير العمر فقط |
| الإشعار العام | Supabase ثم Expo Push | صلاحية محلية ورمز التفويض لكل إرسال، دون حفظ الرمز |

## خطوات الاختبار على Android

1. انشر الإصدار الجديد من واجهة المشروع ثم ثبّت **الحزمة الجديدة** على الجهاز؛ النسخة المثبتة سابقًا لا تحمل التعديلات الجديدة.
2. افتح التطبيق واختر **تسجيل مستخدم جديد**، وأدخل بيانات اختبار غير سريرية وكلمة مرور من 12 محرفًا أو أكثر.
3. ينبغي أن تظهر رسالة تؤكد أن الطلب ينتظر الاعتماد، لا رسالة خطأ اتصال أو TLS.
4. من حساب مشرف أو مستخدم مخوّل، افتح **طلبات التسجيل**، وأدخل رمز التفويض المركزي، ثم اعتمد الطلب.
5. سجّل الدخول بنفس البريد وكلمة المرور. بعد الاعتماد يجب أن يفتح التطبيق كعضو فريق.
6. افتح **الملف الشخصي → تنبيهات الجهاز** واضغط التسجيل لتفعيل الإشعارات. يلزم جهاز Android فعلي وحزمة تطبيق محدثة؛ لا يمكن التحقق من Push خارج تطبيق مثبت على جهاز فعلي.
7. من حساب له صلاحية الإعلان العام، افتح **إشعار عام**، وأدخل رسالة تشغيلية فقط ورمز التفويض المركزي. تظهر نتيجة بعدد الأجهزة المسجّلة التي قُدّم إليها طلب Push.

## نتيجة التحقق المنفذ

أُجريت فحوصات حية عبر HTTPS من بيئة منفصلة، باستخدام بيانات اختبار محذوفة تلقائيًا بعد كل فحص. تم التحقق من إرسال طلب التسجيل، وبقائه معلقًا، والموافقة عليه، وتسجيل الدخول، وتسجيل جهاز Push تجريبي. كما تم التحقق من رفض إرسال Push العام دون رمز التفويض وقبول المسار المصرّح به مع عدم وجود أجهزة مستهدفة.

> لا تستخدم الإشعار العام لمعلومات المرضى أو أرقام الملفات أو النتائج السريرية. استخدم القنوات المعتمدة للطوارئ عند الحاجة.

## ملاحظة تشغيلية

يحتاج إرسال Push الفعلي إلى وجود جهاز مسجّل بالفعل. بعد أن تُحدّث التطبيق وتسجّل جهاز Android من شاشة الملف الشخصي، يمكن تنفيذ تنبيه تجريبي فعلي موجه إلى الأجهزة المسجلة بعد تأكيدك الصريح.
